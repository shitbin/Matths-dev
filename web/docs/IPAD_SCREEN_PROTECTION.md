# iPad 보호 화면과 캡처 무결성 계약

## 가능한 보호와 불가능한 보호

iOS의 일반 SwiftUI 화면은 FairPlay로 보호되는 영상처럼 사용자가 누른 스크린샷 결과를 앱이
강제로 검은 화면으로 만들 수 없다. 비공개 `isSecureTextEntry` 편법도 사용하지 않는다. 대신
GOAT Arena 경기·배치고사·평가 시험지·주간 모의고사·KICE 기출에서 다음을 함께 적용한다.

- 화면 녹화·AirPlay/미러링 감지 중 문제와 풀이를 검은 보호 화면으로 교체
- 앱이 비활성화되는 순간 앱 전환기 미리보기를 검은 보호 화면으로 교체
- 보호 화면에 개인정보가 아닌 실행 단위 8자리 워터마크 반복 표시
- 스크린샷과 녹화 시작·종료를 기기 append-only 로그에 즉시 기록
- 서버 계정은 같은 이벤트를 계정별 오프라인 큐에 보존하고 네트워크 복구 뒤 멱등 전송

## 서버 저장 경계

서버는 다음 세 이벤트만 허용한다.

- `protected-screen-screenshot`
- `protected-screen-capture-started`
- `protected-screen-capture-ended`

클라이언트가 보낸 임의 메타데이터를 그대로 저장하지 않는다. 최대 16자의 실행 코드와 최대
120자의 보호 화면 식별자만 정제해 `metadata.screenIntegrity`에 넣는다. 이 이벤트는 정답률,
풀이 수, 학습 시간, 출석 후보로 계산하지 않으며 자동 제재 근거로 단독 사용하지 않는다.

## 남은 실기 승인

일반 스크린샷은 촬영 뒤 경고와 기록이 남는지, 녹화·미러링은 보호 중 내용이 보이지 않는지,
오프라인에서 발생한 세 이벤트가 재로그인·네트워크 복구 뒤 동일 계정 서버에 한 번만 저장되는지
실기에서 확인해야 한다. 이 증거가 없으므로 추적표 상태는 `구현`이다.
